Supersedes `2026-08-31-iss052-and-1.3.1-release.md`. Its gotcha list is still accurate; this adds
four more and closes ISS-054, ISS-055, ISS-056.

## Start here

`git -C ~/.zug/server log --oneline -1` → HEAD `4af3565`, branch `main`, clean, pushed. npm has
**1.4.0**. Fly is at **v42**. No release tag was cut this time (previous releases tagged `vX.Y.Z`
— worth doing retroactively if you rely on them).

The global `zug-mcp` on this machine is a **symlink into the repo working tree** (`npm install -g .`
links rather than copies), so it follows branch checkouts — check out another branch and the MCP
server silently reverts. `npm i -g zug-mcp@1.4.0` replaces it with a real copy. Left as-is by choice.

## Gotchas — four new

**1. `--auth-type=web` was already documented in the previous handoff and I did not read it.** I ran
a plain `npm publish`, hit `EOTP`, and only learned the flag when Danno said it. Read
`docs/handoffs/` (or run `/story`) BEFORE starting release work — the answer was already on disk.

**2. An npm 409 is not proof nothing shipped.** The failed `EOTP` publish left 1.4.0 **staged**:
absent from the registry's version list and time index, while retries returned
`409 Cannot publish over previously staged version`. It later resolved into a real publish on its
own. Verify against the registry API, not the error text and not `npm view`.

**3. `~/.zug/*.md` is a lagging cache, not live state.** Mid-session I measured PERSONA/PLAYBOOK
from the local files and concluded synthesis was dead and PERSONA frozen. The server's copies were
17 minutes newer and a synthesis had already succeeded. For anything about live behaviour:
`fly ssh console -a zug-mcp -C "cat /data/.zug/users/default/.zug/synthesis-status.json"`.

**4. In synced mode, synthesis runs on Fly.** `server.ts` gates local synthesis behind
`if (mode !== "synced")`. With `ZUG_URL` set, a local rebuild does nothing for PERSONA — only
`fly deploy` does. The three surfaces (Fly / npm / local install) never update each other.

Full flow now written up in `docs/RELEASING.md`.

## Do NOT redo these — shipped in 1.4.0 and verified

- **ISS-054 (resolved).** `synthesize()` re-emitted PERSONA + PLAYBOOK verbatim in ONE call, so
  required output tracked total corpus size rather than the size of the change: 18,438 tokens
  against a 16,384 ceiling. Raising the ceiling was the fix twice before (8192→4096, 4096→16384)
  and had nowhere left to go — the timeout invariant caps it at 21,600 tokens, ~4 weeks at the
  measured growth of ~113 tok/day. Now **one call per document**, so the ceiling is per-document;
  plus compaction as a *verified* control loop (trigger 9,830 / target 6,553 tokens, original
  archived to `PERSONA.archive.md`, `outcome: compaction-failed` recorded when it does not shrink).
  Verified in production: PERSONA 42,317 → 24,816 bytes, `outcome: ok`, headings and `[Nx]` counts
  intact.
- **Two prompt defects found by reading a live run's output**, not by the suite: the prompt's own
  `## Session Summary` heading returned as a PERSONA section, and `[Nx]` reinforcement counts were
  rewritten upward (`[1x]` 17→1, `[2x]` 6→15). Inputs are now fenced; counts are frozen as data.
- **ISS-055 (resolved).** Synthesis inputs were read BEFORE `enqueueSynthesis`, so a task queued
  behind another carried a pre-write snapshot; on success it would overwrite the newer document.
  Both call sites now read inside the task. Regression test gates task 1, queues task 2 behind it,
  and asserts task 2 sees task 1's write.
- **ISS-056 (resolved).** `zug backup` pre-created its destination and `fly sftp` refuses to write
  into an existing path, so it had **never** worked against a Fly install. Parent-only creation,
  `-HHMMSS` suffix for same-day repeats, cleanup on failure. Verified: 373 files, 1.9M.
- **`zug_status` now reports bytes/tokens, not just lines.** Line count is what hid ISS-054 —
  PERSONA went 31→224 lines (7x) while going 1,497→44,750 bytes (30x).
